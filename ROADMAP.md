# cardputerme — Roadmap
> Updated 2026-08-16. #1–#45 shipped; the cycle is **the device you don't have to watch**. Terse; `git log` holds detail.

## What is cardputerme
**Expose ANY terminal to an M5Cardputer with one command.** `cardputerme [name]` (zsh alias → `bin/cardputer-server`) registers this terminal with **ONE Go server per machine** (#44) that owns many sessions on a free port (8001–8255) and broadcasts a **UDP beacon** (port 8000, 2s: `{app,v,name,port}`); the device hears every machine, lists machines **and** sessions in one server-rendered picker, and connects to the one you pick. NO mDNS, NO baked IP. Backend (tmux) invisible & swappable inside `internal/terminal/` only; the whole system = **our Go server + our firmware**. **Really dumb device**: it reports raw events and draws what it is told — body, header and status are all composed server-side (#45), so behaviour changes are server changes, never a re-flash. House rules: no hooks, no regex, no `else`, no model tokens, no code comments, KISS, TDD, **event-driven (no polling)**; device E2E is the user's. North star: **SSH-parity** — only diff vs ssh is the small screen; mirror the terminal's own colors + layout.

## Focus — the device you don't have to watch
#1–#36 delivered SSH-parity and then made it liveable: the mirror dims, sleeps, wakes on a touch, never sleeps on an open prompt, never sleeps on USB. But the device still assumed **you are looking at it**. The user's words: *"to receive a notification I need to keep the Cardputer awake — that is not the purpose of having a Cardputer; the idea is to not need focus on the screen every time."* A pocket terminal you must watch is just a small monitor. **This cycle makes the device earn your attention instead of demanding it.** Most of it has landed: it reports its own power state and battery, the server drives the LED and a real sound, `;notify 1|0` is one switch that persists, a prompt in **any** session reaches you (#44), and the device now composes nothing at all (#45). **What remains is the reason the cycle exists** — an alert still fires only on a numbered question, so Claude *finishing* is silent. Done = you put it face-down, and it gets you when it needs you.

## Done 2026-08-16 (the device earns your attention)
- **#45 The server composes the device header.** The user's challenge: *"why do you need to upload new firmware just to display battery, if the server side should handle what displays at the top bar?"* — correct. `body` and `status` were server-composed; the **header was not**, so the device built WiFi/LIVE/a toast/a page counter from local state and adding battery cost a flash. The frame now carries `header`, a list of coloured runs drawn left to right; `badge` (the previous half-measure) is **deleted** — one string could not carry per-run colour and the device still owned the layout. Deleted from firmware: the WiFi text, `LIVE`, the **entire toast mechanism**, and the fake `1/1` page counter the user complained about. The only local text left is the fallback when `header` is empty (`connecting...`) — the one case no server can speak to is *there is no server*. WiFi became a **reported fact**, parsed as a pointer so an old firmware reads as *unknown*, never `NoWiFi`. Two real bugs found on the way: `SliceIntoCards` **looped forever** on `linesPerCard <= 0` (`i += 0`, reachable from `LINES_PER_CARD=0`), and `sig()` hashed only lines+status+badge so a header-only change never pushed a frame — it now hashes the message the device would draw, which cannot drift as fields are added. **Acceptance test run on hardware: dropped the `LIVE` cell, restarted the server only, header changed — no flash.**
- **#44 ONE server per machine, many sessions.** Reverses the 2026-08-15 server-per-exposure decision on evidence, not theory: `fn+esc` "broke" because the device auto-connected to an exposure running a **pre-picker binary** — N processes means one stale process silently breaks features; #43 existed only because exposures outlive their use; #41 existed only because processes share no memory. `session` was extracted first and landed green before any behaviour change (per-session: backend, subscribe, view, input, history, cache; global: hub, beacon, settings, and the **device-owned** battery/LED/power/idle). Sessions coordinate over **channels** with one dispatcher (`internal/server/events.go`), and `terminal.Subscribe`'s death callback drops a session instead of `os.Exit`. The picker became **one list of sessions and machines**; the `beacons` up-message stays, since the device is still the only party that hears every machine. **The payoff is notifications: a prompt in ANY session now reaches you**, not only the one on screen. `cardputerme` became a **client** that registers with the running server, and a small REST surface (`/sessions`, `/health`) is what the Claude Code skill now integrates against. Bugs found by stress tests and on hardware: a **deadlock** in `drop()` (`stop()` ran holding `mu` while the subscribe goroutine wanted it), a second **deadlock** in `;notify` (commands ran under the lock and called back into it — the user saw the device freeze), races on `s.sess`, `register` creating real tmux sessions, `/health` nil-derefing with zero sessions, and cross-session lag from every session sharing one push.
- **#41 Shared settings, and #40 `;notify 1|0`.** #44 shrank #41 to what it should always have been — persistence, not IPC. `internal/settings` over `~/.cardputerme/settings.json`: a missing file is the normal first run, a corrupt one falls back to defaults **loudly**, unknown keys are ignored so an old binary tolerates a new file, and writes go temp+rename. Precedence is recorded: an explicitly-set env var wins for **that process** (a deliberate one-off), the file is the persisted default. `;notify` is the first command that **changes** state, so it was the real test of the #32b module — and it found the deadlock above. Shipped as ONE switch (`1|0`/`on|off`, bare reports, garbage replies visibly); the `sleep`/`enable` split was dropped as a flag that costs more to explain than it earns. An **empty `SettingsPath` means do not touch disk** — until that was explicit, tests wrote to the developer's real settings file.
- **#42 The server renders the picker; the firmware loses its last menu.** Removes the **last exception** to "the server decides". `drawServerList`, the digit-to-connect branch and `g_autoConnect` are gone; `fn+esc` is now *reported* as a key. The bug that forced it: the device drew from index 0 with no cursor and no scroll offset, so past ~4 rows an exposure was neither drawn nor typeable — **you could lose a server**. Fixing that in firmware would have entrenched the exception, so it was reverted and the list moved server-side, where scrolling and wrap retune without a re-flash. Bootstrap solved deliberately: with no connection there is nothing to render, so the device auto-connects to the first beacon as **transport** and reports `{"type":"beacons",…}` — a raw fact, since only the device hears every beacon. Selection returns `{"type":"connect",…}`. The picker is an **ordinary display frame** — one rendering path, one input path. Verified on hardware: `fn+esc` opens the list, enter connects.
- **#39 Server-driven RGB LED + sound.** `led` and `sound` are **primitives the server may send at any time**, not notification hooks; the device renders and decides nothing. `neopixelWrite` on GPIO21 (no new library), and `tone` or a WAV fetched over HTTP — audio **cannot** ride the WebSocket (frames ≥15KB crash-loop the device), so the server serves `~/.cardputerme/sounds/` and sends a **complete URL** minted from the WS connection's local address (correct on a multi-homed host). MP3 is converted on the computer, never by the Go server, which must stay a CGO-free static binary. Two bugs found on device: LED-off was tied to `!awaiting` (recomputed every ~15ms, so detection flicker extinguished it), and `setLed`'s dedupe desynced after a reconnect because the device boots dark — LED state is now re-sent on connect exactly as `power` is. **HARDWARE LIMIT:** on the ADV, LED power (`PWR_EN`, GPIO38) shares the backlight line, so the LED **cannot** light with the screen fully off. Sound is the pocket channel.
- **#43 Exposures self-stop when idle.** An exposure only self-exited when its *terminal* died, so a server nobody had talked to in hours kept a port and beaconed every 2s — the user had four listed, two of them stale. `internal/idle` is a pure deadline in the shape of `internal/power`: armed at startup, reset on connect/disconnect, one `AfterFunc`, no polling. `IDLE_EXIT_H=12`, **0 = never**. An **open connection suppresses it** — a device connected for days reports only on change, so silence is not absence. Never touches the user's tmux session.
- **#37 Battery + charging in the status bar, and the jumping percentage fixed.** The bar shows `87%`, `+87%` on external power, and **nothing** until the device has reported (0% must never read as real). The percentage is derived **server-side from `mv`** and the firmware's `battery` field is ignored: `getBatteryLevel()` is pure arithmetic, so it is a *decision*, and deriving it server-side means the curve and smoothing retune without a re-flash. The jitter was real and quantified — the mapping spans 800mV across 100% (**1% = 8mV**) while the ESP32 ADC is **±50mV** (±6 points), and waking drives the backlight `0/40→255`, sagging the rail. Answered with a median window, a display deadband, never-rises-while-discharging, and **discarding readings within ~2s of a server-commanded power transition** — the server knows when it caused the sag. Charging is **inferred** (the ADV has no charge line): `usb || mv >= USB_MV || sustained rise`, the trend term added because `USB_MV=4200` sits *above* the mapping's own 100% ceiling of 4100.
- **#20 Server-owned idle sleep (power ladder) — E2E passed on hardware** *(tracker 406 + 423)*. `internal/power` = pure `Policy`/`Tracker`, ladder `on→dim→off` (14 tests). `applyPower`/`armPowerTimer` arm ONE `time.AfterFunc` off `Tracker.Until` — event-driven, no tick; `{"type":"power","state":…}` broadcast on transition only; `lastAwaiting` drives `SetInhibit` so a pending prompt never sleeps; state re-sent on ws connect. `DIM_AFTER_S=30`/`OFF_AFTER_S=120` (0 = never). Firmware maps `power` → `setBrightness` 255/40/0; **G0 toggles sleep/wake** (pocket it). User-verified on device: dim@30s, off@2min, WS survives sleep (no reconnect — the reason sleep is backlight-only), first key on a dark screen swallowed, a dim screen passes the key (#26), G0 pockets, an open prompt stays lit.

## Done 2026-08-15 (Go era)
- **#32b Commands live in their own module; `;help` lists them.** Per the user: one explicit place to add commands. New package **`internal/commands`** — `Ctx` (what a command may see of the server), `Command{Help, Run}`, an unexported `register`, and `Run`/`List`. **`builtin.go` is the whole surface: `ping` and `help` are registered there and that is the only file you touch to add a verb.** `register` is unexported on purpose, so "all commands live in one module" is enforced by the compiler rather than by convention, and `init()` is load-bearing — a map literal cannot compile because `help` refers to `List` which refers to the registry (initialization cycle). Replies now render **as output lines**, not in the status bar, because a reply is a response (user call). Simplify pass caught a real defect: `List` joined entries with two spaces, but `WrapLine` runs `strings.Fields` and *discards* the separator, so `;help` came out as `;help - list commands ;ping - answer…` run together mid-word; entries are newline-joined and the renderer splits on newlines, so each command gets its own row. Also: the `;` prefix no longer round-trips (input strips it, so the module's contract is verb+args), one `add` closure replaced three copies of wrap-and-colour, `notice`→`reply`, and my stray probe file is gone. 215 tests, `-race` clean.
- **#32a Device commands — `;ping` → `Pong!`** *(milestone 424 / task 425)*. A second channel that is **not** terminal input: `;` on an EMPTY buffer opens a command line, Enter runs a server-side verb, esc cancels. `;` because on the Cardputer it is the same physical key as fn+up — no shift needed (`:` would have). With a non-empty buffer it stays a literal `;`, so `for i in 1 2 3;` still reaches the shell. A command **never** reaches tmux: `Action{Kind:"command"}` is handled before the backend switch, and a test asserts no keystroke of `;ping` produces `send`/`pressKey`. Adding a verb is **one map entry** in `internal/server/commands.go` — the registry lives server-side because commands need server state, while `internal/input` stays dependency-free. `Repeat` is false so hold-to-repeat cannot run a command twice. **No protocol change and no re-flash** — the command line and its reply ride the existing `display` frame. 208 tests, `-race` clean. Scope call: `:link`/QR and the browser mirror (426/427) dropped.
- **#36 Hint rows can be hidden (`HIDE_PREFIXES`, default `Tip:`).** A tip line is only identifiable by its text, and the house rules forbid app-specific matching in code — so the *mechanism* is generic and the app-specific part is **configuration**: `screen.StartsWithAny` drops a row whose visible text (after ANSI + tree markers are stripped) starts with a configured prefix, and `HIDE_PREFIXES` supplies the list. Matching is case-sensitive so ordinary prose survives, an empty prefix is ignored (it would hide everything), and with no config nothing is hidden. Retunes without a re-flash. 185 tests, `-race` clean.
- **#35 The app's own input box is no longer mirrored.** The placeholder inside it (`Press up to edit…`, `Try "edit <file>"`) was spending a row on a six-row screen for text the user cannot act on — and the server already renders its *own* input line from `s.input`, so the widget was pure duplication. `framedRows` marks rows enclosed by a **nearby pair of rule rows** (the box the widget is drawn in) and `splitScreen` drops them. The gap bound (`maxFramedRows=4`) is the safety valve: an unpaired rule in ordinary output must not swallow the transcript behind it, and a wide gap between two rules is a *section*, not a widget — both are tested. Structural, so no app-specific string is matched. 177 tests, `-race` clean.
- **#34 The conversation name moved to the status bar.** Terminal UIs frame their input box with a box-drawing rule that carries a label — `───── my-session ──`. `ToAscii` folds the `─` away, so that row reached the device as a bare title and ate one of only **six** body rows. `screen.RuleTitle` (pure, 8 tests) now recognises a row as a horizontal rule (`─ ━ ═`, >=8 of them) and extracts any embedded label; `splitScreen` drops rule rows from the grid and hands the label up, and `composeMirror` prefixes it to the status bar. Generic by construction — it keys off the row's **structure**, never an app-specific string, so any framed TUI benefits. First slice of the #27 chrome work. 173 tests, `-race` clean.
- **#31 Never sleep while on USB power** *(task 422, under milestone 406)*. Plugged in there is no battery to save, so the ladder must not dim or blank. Hardware constraint found first: Cardputer ADV is `pmic_adc` (battery volts on ADC1_GPIO10, **no charge-status line**), so `isCharging()` returns `charge_unknown` — the device *cannot* report "charging". So the firmware reports raw facts only — `{"type":"report","usb","mv","battery"}` on WS connect and **only when a value changes** (sampled in the existing loop, 40mV hysteresis, no send-timer) — and the **server** decides: `onExternalPower(usb, mv, USB_MV=4200)` feeds `power.Tracker.SetExternalPower()`, a second inhibitor beside the prompt one. `Until()` returns 0 while set, so no rung is armed at all; a deliberate G0 sleep still outranks it (pocket it while charging); unplugging restarts the countdown from the unplug moment. The threshold is server-side, so it retunes without re-flashing. Caveat: the USB-CDC flag only trips when a host opens the port, so a dumb charger is caught by the voltage threshold alone — reliable on a computer, best-effort on a wall plug. 158 tests, `-race` clean.
- **#30 Output latency + repeat coalescing.** **(4)** The 40ms debounce never covered the keystroke echo (that always broadcast immediately) — it gates **terminal output**, which is the part that felt slow. Now `PUSH_DEBOUNCE_MS=15` (`pushAfter()`, env-tunable); safe to shorten because #29's per-client coalescing absorbs any extra frames. **(5)** A held key that ticks late now catches up in ONE tmux call instead of falling behind: `Holder.Due()` reports how many intervals elapsed, `applyKeyTimes` pans that many rows or sends `tmux send-keys -N n` (`sendKeyArgs`), capped at `maxCatchUp` 8 so a suspended process can't fire an avalanche. Normal ticks are `n=1`, i.e. byte-identical behaviour — the win shows up only when the server stalls. Note fn+arrow panning never touched tmux at all (it is pure viewport maths), so #5's fork saving applies to opt+arrow keys sent into the terminal. 147 tests, `-race` clean.
- **#29 Less friction between the keyboard and the response (faster + consistent).** Three changes. **(1) Batched key events** — one keyboard scan now sends ONE frame `{type:keys,events:[{key,state}...]}` instead of up to four (a char, `del`/`tab`/`enter`, plus the release); `{type:key,...}` still works, and a missing `state` is still a tap, so no flag day. **(2) A write deadline** — `hub.broadcast` called `WriteMessage` with no deadline *while holding the hub mutex*, so one slow device stalled every push and lag accumulated without recovering; each client now has its own writer goroutine (gorilla requires exactly one writer per conn) and a 5s deadline. **(3) Frame coalescing** — display frames land in a per-client `mailbox` where the newest replaces the pending one, so a device that falls behind renders the *current* screen instead of a backlog; power/notify go on a bounded ordered queue and are never dropped. Matches how RFB/VNC handles a slow client (coalesce transient states, never queue them). 138 tests, `-race` clean.
- **#28 /simplify pass (4 parallel review agents) on server + firmware.** Applied: repeatability became a property of the interpreted action (`input.Action.Repeat`, set where the intent is decided) — deleted `repeatArrows`, which duplicated `input.arrows`, and fixed the layering bug it caused (repeat was decided *downstream* by pattern-matching emitted actions). One `deadline` type now owns arm/stop for both the power and repeat timers, replacing two copies of the same mutex+`*time.Timer` dance. **The wake-swallow rule moved off the device** — firmware just lights the screen and reports the key; `keyDown` decides to swallow when the ladder is `off`, so the policy can change without re-flashing. Echo frames are deduped against `lastSig` (a held key was re-rendering and broadcasting up to ~11 identical full frames/sec to a battery device). Also: `EnsureSession` reports created-vs-attached so startup probes tmux once instead of twice, `tmuxTarget`→`sessionTarget` + `SESSION` (no tmux naming outside `internal/terminal`), `Holder.Release`/`Fired(now)` dropped, `SESSION_CWD` resolved once, firmware `String g_heldKey`→fixed buffer (no per-keystroke heap churn). Skipped with reasons: filtering `up` events on the device and dropping `"state":"down"` (both would put policy back in firmware, against the standing rule), timer `Reset` reuse and tmux `send-keys -N` coalescing (micro-optimisations with real race/complexity risk).
- **#25 Hold-to-repeat navigation (server-owned).** Holding an arrow now scrolls continuously instead of one line per press. Firmware sends the **press and the release** (`{type:key,key,state:down|up}`, `sendKey`/`releaseKey`/`handleKeyboard`); the server decides everything else. `internal/repeat` = pure `Policy`/`Holder` (`Down`/`Up`/`Fired`/`Next`/`Key`, 9 tests): first repeat after `REPEAT_DELAY_MS=350`, then every `REPEAT_INTERVAL_MS=90`, arming ONE `time.AfterFunc` per tick off `Next()` — same event-driven shape as the power ladder, no loop. **`MaxHold` 10s** stops a runaway when a release packet is lost. Only navigation repeats (`repeatableAction`: `pan`, and `pressKey` of an arrow) — holding a letter, enter or zoom never repeats. A message with no `state` is still a plain tap, so an un-flashed device keeps working.
- **#26 A dimmed screen no longer eats your keystroke.** `handleKeyPress` swallowed the first key whenever `g_power != POWER_ON`, so after 30s idle (dim, still perfectly readable) the next keypress vanished into a `wake` — felt exactly like lag. ## Reference
- **Install:** `curl -fsSL https://raw.githubusercontent.com/brutalzinn/cardputerme/main/install.sh | sh` (checksum-verified; `CARDPUTERME_VERSION`/`CARDPUTERME_BIN_DIR` override). Release = push a `v*` tag (CI auto-publishes); native macOS Intel/ARM + Linux amd64/arm64, static.
- **Run:** `cardputerme [name]` — **ONE server per machine** (#44), not per exposure. The CLI is a **client**: it reads `~/.cardputerme/server.port`, health-checks, and `POST`s `/sessions` to register this terminal; it starts the server only if none is listening. Free port 8001–8255, log `~/.cardputerme/server.log`; **the session is named after the project dir** (argv[1] or `NAME` override) while capture attaches to *this* terminal's tmux session (`TMUX_SESSION`/`SESSION`). One beacon per machine: UDP 8000 every 2s (subnet-directed + limited broadcast). REST: `GET /sessions`, `POST /sessions`, `GET /health` — what the `/cardputer` skill integrates against.
- **Release state:** latest tag is **`v0.0.4`** (at `115dc23`, #23) — **35 commits stale**, so `install.sh`'s `latest` ships without #24–#45. Cut `v0.1.0` (Day 1 #2): the wire broke, so **firmware and server must be upgraded together**.
- **Settings (#41):** `~/.cardputerme/settings.json` — **persistence, not IPC** (one server holds them in memory since #44). A `;` command retunes every session, not just the one you're mirroring. Missing = defaults; corrupt = defaults + a loud log; unknown keys ignored; temp+rename writes. An explicitly-set env var overrides for **that process only**. `;notify 1|0` is the one switch — sound is the pocket channel, since the ADV LED cannot light with the screen off.
- **Battery:** the ADV **cannot** report charge status (M5Stack: *"Cardputer and Cardputer-Adv cannot read battery charging status or battery current information"*; `isCharging()` → `charge_unknown` on plain-ADC boards). Charging is **inferred** server-side by `onExternalPower` = USB-CDC flag OR `mv >= USB_MV` (4200). The CDC flag only trips when a host opens the port, so a dumb wall charger falls back to the voltage threshold alone.
- **Tests:** `cd server-go && go test ./...` · `go vet ./...` · `go run golang.org/x/tools/cmd/deadcode@latest -test ./...`. **Flash:** `cd firmware/cardputer && $PIO run -e cardputer-adv -t upload` (device `/dev/cu.usbmodem21201`; E2E is the user's; only Wi-Fi creds in `firmware/.env`).
- **Screen sleep:** server owns it (`ext-idle-notify-v1` shape) — dim 30s, off 2min (`DIM_AFTER_S`/`OFF_AFTER_S`, 0=never); any key wakes (first press swallowed), **G0 = sleep now / wake**; an unanswered prompt never sleeps. Sleep = backlight off, WS stays up (deep sleep would drop the socket).
- **Protocol:** ONE WebSocket contract is the only extension point. The **server is mandatory and authoritative** — it owns the terminal and all state/policy (input, history, viewport, zoom, sleep, repeat) and runs fine with zero clients. A **client is a thin, replaceable renderer** that draws what it is told and reports raw events; the Cardputer is one client, the #32 browser view is another. Behaviour changes are therefore server changes — no re-flash. Down: `display` (`body` + **`header`** + `status`, #45) / `power` / `led` / `sound` / `connect`; up: `keys`/`key`/`report` (`usb`,`mv`,**`wifi`**)/`beacons`/`wake`/`sleep`/`cmd`. **`notify` is currently dead on the wire** — #45 deleted the toast that consumed it; #38 decides whether it returns or the header replaces it. Frames are absolute (so coalescing and late joins are safe); unknown types are ignored; a `key` without `state` is a tap. Full spec in `llm/protocol.md`.
